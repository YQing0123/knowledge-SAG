# SAG 知识库检索技能

本技能让 DSH 当前会话直接使用 Docker 中运行的 SAG 知识库（`http://127.0.0.1:8000` API / `http://127.0.0.1:3000` Web）：

- **检索归 SAG**：SAG 检索引擎（语义 + 事件-实体关系扩展）负责从知识库取出证据分块。
- **生成归本会话模型**：你负责理解问题、判断检索策略、用证据生成带引用的答案。
- 这是对 SAG 内置对话（其自带 LLM）的升级：模型更强、上下文完整、可多库 @ 选择。

> **选库方式（会话内）**：用户不需要记忆库 id——直接对模型说「用知识库 X / Y」或输入 `@知识库名`；模型会先调 `sag_list_sources` 把名称解析成 id 再检索。若用户想先看看有哪些库，直接问「有哪些知识库」，模型就列出全部库（名称/文档数/分块数）供选择。多库同时选：`@库A @库B` 或「用 A 和 B」。

## 工具

- `sag_list_sources`：列出全部知识库（信源）→ id/名称/文档数/分块数。**@ 解析前必须调用**。
- `sag_search`：按 query 检索证据。参数：
  - `query`（必填）：问题或关键词
  - `source_ids`（可选）：限定到用户 @ 选择的若干知识库 id
  - `top_k`（可选）：证据条数，默认 8
  - `strategy`（可选）：`multi`（精确，默认）或 `vector`（快速）

## 用法

### 1. `/sag <问题>` —— 快速唤起

用户输入 `/sag ...` 时，视为明确要求使用 SAG 检索回答问题：

1. 若用户用 @ 指定了知识库（如 `/sag 什么是SAG @产品文档 @论文`)：
   - 先调 `sag_list_sources` 拿到 id 映射；
   - 把 @ 名称解析为 `source_ids`；
2. 调 `sag_search`（带或不带 `source_ids`）；
3. 基于返回的证据分块生成答案，引用时标注来源（信源名 / 分块标题）。

### 2. 自主检索（无需 /）

当问题明显依赖知识库中的事实、原文或出处（用户提到"资料""文档""知识库""之前上传的"等，或对话上下文存在已选择的知识库）时，**不要凭空回答**，先调 `sag_search`。可多轮改写 query 直到证据充分；信息仍不足时向用户澄清，不臆造。

### 3. @ 选库多库对话

- 用户在会话中 `@知识库名` 表示限定检索范围。
- 规则：先 `sag_list_sources` 解析名称 → id（名称匹配优先精确，其次包含；找不到时列出相近名称询问用户）。
- 一次回答可同时检索多个库（`source_ids` 传多 id），合并证据后统一回答。

## 证据与引用

- 检索返回的 `evidence[]` 每项含 `source_name`（信源）、`heading`（标题）、`content`（原文证据）、`score`。
- 回答时：**基于证据内容作答**，关键论断后标注来源，例如 `（来源：产品文档《…》片段）`。
- 若 `evidence` 为空：换关键词、收窄/放宽 `source_ids`；若确认库中无相关文档，如实告知并提示先到 SAG 面板（侧边栏 SAG 知识库 → 知识库管理）上传文档。

## 边界

- 寒暄/致谢/纯创作/简单计算等不依赖知识库的问题：不要调用检索工具。
- 不修改 SAG 数据（本技能只读检索；上传/管理请用界面）。
- SAG 服务未启动或登录失败时工具会报错：转告用户检查 Docker（`docker compose ps`）与网络。
